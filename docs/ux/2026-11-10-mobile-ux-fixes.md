# Mobile UX fixes — 10 November 2026

Addresses the 18 findings from the first platform audit and 10 findings from the mobile stress audit. This is a refinement of the current UI, using the existing mobile frame (maximum 430px). No XP/Trust/IDW formula, publication policy, database schema or Admin permission changes.

## Validation

- Frontend unit tests, format, lint, TypeScript and production build.
- Mobile touch E2E at 320, 360, 390 and 430px, including new regression cases in `e2e/mobile-ux-regressions.spec.ts`.
- Existing swipe regression preserves continuous report scrolling while retaining access to Close.
- Populated AQI contrast across five bands, expired readings, actual 200% root text, direct-entry Back, preferences/LINE failures, inline confirmations and focus restoration.
- Fake-camera cancellation probe waits for the delayed media promise and verifies late tracks stop.
- Repeat 1,000 isolated browser sessions across mobile viewport heights and root text scales. These are simulated journeys, not 1,000 people or a 1,000-concurrent-user load test.
- Visual inspection of short-screen sheets and 200% legal reflow.

Machine-readable results and screenshots are local artifacts under `test-results/mobile-ux-fixes/` (ignored by Git).

Initial fix verification: **390 unit tests passed; 293 distinct E2E cases passed after targeted rechecks; 6 viewport-duplicate cases skipped; 1,000 simulated sessions passed 6,300 checks**. The full run initially had one camera-fixture timeout; the fixture was corrected to guarantee a delayed successful fake-media result, then the affected test passed. New browser regressions also verify actual cluster focus and secondary target geometry after CSS cascade. The combined local results are in `test-results/mobile-ux-fixes/verification-summary.json`.

## Limits

Real iPhone/Android camera, gallery, GPS accuracy, native keyboard/safe-area behaviour, VoiceOver/TalkBack, OAuth/logout and LINE delivery still need device/account validation. Browser fixtures establish UI behaviour and do not certify those integrations. Local audit and simulated user journeys do not write to Production. Deployment acceptance is recorded separately after the explicitly authorized rollout.

## Release recheck

The release review additionally guards stale camera start/fallback results from modifying a newer camera session, actively removes expired private drafts from memory, propagates returned sign-out errors to the retry UI, and avoids reliance on the newer `checkVisibility` browser API. Regression cases cover delayed fallback rejection after a new camera opens, expiry without a subsequent read, replacement-draft expiry, and returned sign-out errors.

The committed Playwright configuration now enables mobile/touch emulation at 320/360/390/430px. The place-card resize case stays within 430px.

Pre-release checks: 294 mobile E2E cases passed in one full run (6 duplicate-viewport cases skipped); 393 frontend unit tests passed with coverage gates; 567 backend tests passed at 81.27% coverage; all eight isolated SQL contract suites passed; npm audit, format, lint, TypeScript and production build passed. The rollout makes no schema or feature-flag changes. Actual deployment/production smoke results are separate from simulated device acceptance.
