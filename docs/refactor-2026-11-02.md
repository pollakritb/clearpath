# ClearPath refactor — 2026-11-02

## Purpose and boundary

Make the current codebase easier to read and present without changing the latest
Place IDW, lifetime-XP rank policy, report publication, Trust, identity/privacy,
measurement-request behavior or Like/Dislike/Comment.

This work is local only. No commit, push, deployment, or remote database
query/mutation was performed. The starting revision is
`ea461c48095c9ec01e737bfb7fb1f9d06e73c51d`; historical implementations remain in Git.
Existing migration files and the untracked Supabase CLI cache were preserved.

## Changes

- Removed unused NationalSummary, LeaderboardEntryCard, FalseSafeCaseReviewList,
  ReviewQueue, DataIssueForm and panel style exports, plus their stale callers/mocks.
- Removed new data-issue submission. Admin still reads historical issue/audit data;
  Like/Dislike/Comment remain. The server-side star/Trust compatibility path remains.
- Removed dormant administrator write services and unused write request models.
  Renamed the announcements panel to match its read-only role.
- Removed the local/ML forecast, shadow/canary/model-release, prediction-ledger,
  provider-selection and telemetry pipelines, their dedicated tests/scripts,
  dormant workflow and XGBoost development dependency. Kept CAMS collectors,
  grid publication, retention and current field/OCR/interpolation evaluation tools.
- Kept authenticated retired endpoints as empty/unavailable/paused responses.
  Setting an old pause flag to false cannot access retired storage.
- Kept `requirements.txt` as the production dependency source for package metadata.
- Split the old 2,395-line persistence file into four domain query modules and an
  independent shared client. The old module is a stable re-export boundary.
  Each domain imports independently; a fresh-process regression test guards cycles.
- Batched measurement invitations, help claims, result reports, public identities
  and recipient counts. The query regression covers 10/100/251 requests,
  ownership fields, alias presentation and pagination without per-row storage reads.
- Moved map orchestration into `useMapPage`, with a tagged station/report/request
  target and separate place/stack context. Kept deep links, map persistence,
  history/CAMS transitions and completed-request hiding.
- Grouped small Leaflet behavior components, reused filtered request rows, removed
  the constant-disabled forecast preview and shared upload validation for main/burst images.
- Consolidated user refinement/XP/account/flow styles into the user stylesheet,
  removed obsolete preview/review rules and redundant overridden declarations,
  preserving mobile frame behavior. Section comments identify each style group.
- Kept XP compatibility fields `minimum_days`/`next_days` at 0/null and added a
  contract check for frontend/server rank thresholds. No reward or Trust formula changed.
- Updated E2E expectations that still referred to superseded UI labels, manual OCR,
  writable Admin screens or a desktop-width card. Regression checks now exercise
  the current UI. Presentation artifact generation is opt-in so normal tests cannot
  overwrite slide images: set `CAPTURE_PRESENTATION_SCREENSHOTS` when running that suite.

## Presentation walkthrough

1. `app/layout.tsx`: mobile frame, authentication, persistent map and route boundaries.
2. `MapPageClient` → `useMapPage`: UI composition, typed target selection and data hooks.
3. `frontend/lib/api-client.ts`: the single typed `/api/*` browser boundary.
4. `backend/routers/community.py` → `services/community/`: draft, OCR publication,
   privacy-safe presentation, engagement and XP as separate responsibilities.
5. Measurement service/store: request lifecycle and batch loading; demonstrate its query-count test.
6. Pure algorithms: haversine, IDW, community eligibility and XP rank policy.
7. Stored CAMS: raw snapshots and ready grid generations, with no local model fallback.
8. Domain stores → shared client → existing database ERD/data dictionary.

The backend gap-fill policy and frontend 2km Place IDW are intentionally different.
The former station fresh/delayed 60/90-minute distinctions are retained; this
refactor does not silently reconcile or change those algorithms.
