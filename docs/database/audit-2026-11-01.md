# Database audit — ClearPath_Final, 2026-11-01

**อัปเดตหลัง audit:** ผู้ใช้อนุมัติและลบ `weather_observations`, `fire_feature_snapshots`, `forecast_data_quality_daily` ที่ว่างแล้วผ่าน migration `20261101065151`. ปัจจุบันเหลือ 41 ตาราง. รายการและตัวเลขด้านล่างเป็น snapshot ก่อนลบ; layer satellite hotspot ผ่าน FIRMS ยังอยู่.

ตรวจผ่าน Management API และเทียบ backend/SQL/RPC/cron. เป็น snapshot ณ การตรวจ; จำนวนแถวเปลี่ยนตาม ingestion. ไม่มีการลบข้อมูลจากการ audit นี้.

## ข้อสรุป

ยังไม่พบตารางที่ยืนยันว่าเลิกใช้ทั้งหมดและ drop ได้ทันที. ตารางว่างไม่ใช่หลักฐานว่าไม่ใช้ โดยเฉพาะ queue/lease/control และตารางชุมชนหลังเริ่มบัญชีใหม่. ขนาด database ประมาณ 57.4 MiB, WAL ประมาณ 128.0 MiB; ไม่ใช่ total disk และไม่ใช่การรับประกันขนาดในอนาคต.

## จุดที่ควรปรับ

1. `forecast_provider_snapshots`: มี 35,400 แถว ประมาณ 23.6 MiB รวม index ณ การตรวจ เป็น 2 รอบล่าสุดของสถานีทั้ง 6 batches ไม่ใช่หลักฐาน exact duplicate. หากไม่ต้องใช้ย้อนหลังหลาย issue ให้เก็บ 1–2 รอบสำเร็จต่อ batch และคงรอบก่อนหน้าจนรอบใหม่ครบ พร้อม future valid times. หากต้องรักษาหลักฐานย้อนหลัง 72 ชม. ต้องคง policy เดิม; การลดเหลือรอบล่าสุดเป็นการเปลี่ยนนโยบายข้อมูล.
2. `private.identifier_aliases`: ประมาณ 12.2 MiB ส่วนใหญ่เป็น snapshot aliases. ตรวจ consumer ของ UUID telemetry ก่อนลด mapping ต่อแถว; mapping ชุมชน/privacy/retry ต้องเก็บ. Policy ปัจจุบันล้าง telemetry aliases เมื่อปลายทางถูกลบแล้ว.
3. `capture_sessions`: พบ 2 session หมดอายุและไม่มี FK อ้างอิงจาก report/draft/evidence. เพิ่ม cleanup แบบ bounded และตรวจการอ้างอิงซ้ำ ณ เวลาลบ ไม่ drop ตาราง.
4. เติม retention ของข้อมูลชั่วคราวที่ยังไม่ครอบคลุมใน private history cron: session กล้อง, outbox ส่งแล้ว, lease หมดอายุ, map events เก่า และ notification ที่อ่านแล้ว. ต้องกำหนดอายุให้ไม่ทำให้ retry/dedup/history ของผู้ใช้เสีย; ตารางเหล่านี้เกือบทั้งหมดว่างตอนตรวจ จึงยังไม่ใช่ปัญหาพื้นที่ปัจจุบัน.
5. `weather_observations`, `fire_feature_snapshots`, `forecast_data_quality_daily` ว่างและอยู่กับ pipeline โมเดลที่พักไว้. รวมกันประมาณ 48 KiB; ลดพื้นที่ได้น้อย. ถ้าประกาศเลิกโมเดลนี้ถาวร ให้ถอด service/admin/readiness/export/test/retention dependencies ก่อน drop. ห้ามสรุปว่าไม่ใช้เพียงเพราะ pipeline ปิดอยู่.
6. คงโปรไฟล์, รายงาน, evidence, Trust/XP, consent, settings และ private Storage ตามนโยบายของ feature ไม่ใช้ cutoff 3 วันแบบเหมารวม.

## Retention ที่มีแล้ว

`clearpath-recent-history` ทำงานทุก 10 นาที ล้างประวัติทางการ/forecast ตาม cutoff 72 ชั่วโมงแบบจำกัด 1,000 แถวต่อตารางต่อรอบ, ล้าง provider runs ที่ไม่มี snapshots, กริดเก่าที่ไม่ active, telemetry aliases ที่ไม่มีปลายทาง และ cron logs เก่า. `rate_limit_windows` ล้างแล้ว. การลบแบบธรรมดาช่วย reuse พื้นที่ ไม่ได้ทำให้ไฟล์เล็กลงทันที; ไม่เสนอ VACUUM FULL บน Free ที่พื้นที่จำกัด.

## หลักฐานในโค้ด

- `backend/routers/cron.py`: primary ingestion และการข้าม pipeline เมื่อ forecast_system_paused.
- `backend/services/provider_sync.py`: เก็บ CAMS เป็น 6 batches; issue timestamps แยกรอบข้อมูล.
- `backend/services/forecast_grid_store.py`: active grid, generations, frames และ chunks.
- `backend/services/community/xp.py` และ RPC `process_community_xp`: queue XP ที่ไม่มี direct Python table reference.
- RPC `take_rate_limit`, `claim_measurement_delivery`: ตาราง rate limit/lease ยังใช้แม้ไม่เห็น `.table(...)` ใน Python.
- `backend/services/retention.py`: purge evidence/draft ตามนโยบายรายงาน.
- `supabase/bootstrap/recent_history_retention.sql`: bounded history cleanup ปัจจุบัน.
