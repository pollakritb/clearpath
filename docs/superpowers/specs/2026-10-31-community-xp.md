# ClearPath participation XP v1

การเปิดแจก XP บน production แยกจากการ deploy โค้ด/schema และต้องทำตาม runbook

## กติกาที่ปรับแล้ว

- รายงานที่อนุมัติและสดไม่เกิน 3 ชั่วโมงขณะส่ง: **10 XP** สูงสุด 5 รายงานต่อวัน
- ช่วยคำขอที่เริ่มก่อนถ่ายภาพและผ่านหลักฐาน: **เพิ่ม 5 XP** สูงสุด 3 ครั้งต่อวัน
- รายงานเดียวจึงรับได้ **15 XP**; สูงสุด **65 XP ต่อวัน** ตาม Asia/Bangkok
- ช่วงห่างระหว่างรายงานที่ได้รับ XP อย่างน้อย 30 นาที นับเวลาอนุมัติจาก server
- หากโควตารายงานปกติเต็ม แต่โบนัสยังเหลือ รายงานยังรับโบนัส 5 XP ได้เมื่อผ่านช่วงห่างและเงื่อนไขโบนัส
- Reversal ไม่คืนโควตาหรือช่วงห่างที่ใช้ไป เพื่อกันวนใช้สิทธิ์ซ้ำ แต่หัก XP และคำนวณยศ/วัน/Badge ใหม่
- ภาพซ้ำ รายงานไม่ผ่าน OCR ข้อมูลเกินอายุ และกิจกรรมทางสังคมไม่ให้ XP ไม่มีโทษ XP จากข้อผิดพลาดทางเทคนิค
- ไม่มี XP สำหรับการสร้างคำขอ ให้ดาว ไลก์ หรือความคิดเห็น และไม่มีรางวัลทางการเงิน
- การอนุมัติรายงาน เกณฑ์ภาพ/GPS เดิม Trust และน้ำหนัก IDW คงเดิม XP ไม่ใช่ input ของระบบเหล่านั้น

## โบนัสคำขอ

ต้องกดเริ่มช่วยก่อนถ่าย วัดและส่งในหน้าต่างคำขอ ภาพไม่เกิน 15 นาที และ GPS ที่รับใหม่อัตโนมัติตอนส่งมี accuracy ≤200 เมตร อยู่ห่างจุดวัด ≤200 เมตร และจุดวัดอยู่ในรัศมีคำขอ

ภาพจากคลังที่ผ่านระบบส่งรายงานเดิมยังรับ XP ปกติได้ แต่โบนัสต้องมีเวลา EXIF และ GPS ที่พิสูจน์ได้ เงื่อนไข XP ไม่ผ่อนเกณฑ์รับภาพเดิม และไม่เพิ่มช่องกรอกเวลา/พิกัดเอง

- คนละบัญชีกับผู้ขอ หนึ่งคนต่อคำขอ หนึ่งโบนัสต่อรายงาน
- คู่ผู้ขอ/ผู้ช่วยเดียวกันรับได้ 1 ครั้งต่อวัน และ 3 ครั้งใน rolling 7 วัน
- คนแรกทำให้คำขอสำเร็จตามเดิม คนที่เริ่มไว้แล้วมีเวลาถึง min(เวลาหมดอายุเดิม, สำเร็จ +15 นาที)
- ห้ามเริ่มภารกิจใหม่หลังสำเร็จ ไม่มีโบนัสคนแรก
- การยกเลิกปิดสิทธิ์ใหม่ทันที ใช้เวลาอนุมัติจาก server ประเมินสิทธิ์งานที่ค้างใน queue เพื่อไม่ให้การ retry เปลี่ยนผลย้อนหลัง
- รายงานที่ไม่เข้าโบนัสยังเผยแพร่ตามนโยบายเดิม และได้คะแนนปกติถ้าเข้าเงื่อนไข

## ยศตลอดชีพ

เกณฑ์ XP คงเดิม เพราะรายงานปกติยังได้ 10 XP การลดโบนัสทำให้คำขอเป็นแรงเสริม และไม่ทำให้พื้นที่คำขอน้อยเสียเปรียบ

| ยศ               |    XP | วันที่มีผลงานรับ XP |
| ---------------- | ----: | ------------------: |
| นักสำรวจอากาศ    |     0 |                   0 |
| ผู้รายงานชุมชน   |   100 |                   3 |
| ผู้ร่วมดูแลอากาศ |   500 |                   7 |
| ผู้พิทักษ์อากาศ  | 1,500 |                  20 |
| แกนนำอากาศสะอาด  | 5,000 |                  60 |

ต้องผ่านทั้งสองเงื่อนไข ไม่ต้องทำต่อเนื่อง ยศไม่ลดเมื่อพักใช้ แต่คำนวณใหม่เมื่อมี reversal ของ XP ทุจริต Badge: รายงานแรก / ช่วยคำขอแรก / ช่วยครบ 10 / ช่วยครบ 50 ไม่มีคะแนนซ้ำจาก Badge

## UX และความเป็นส่วนตัว

หน้า `/leaderboard` เปิดจากโปรไฟล์ แสดง XP ยศ ความคืบหน้า วันทำผลงาน และตัวกรอง all/7d/30d อันดับร่วม 1,2,2,4 ไม่ใช้ Trust ตัดสิน โหลดครั้งละ 50 ราย ผู้ชมทั่วไปดูอันดับได้ เจ้าของเห็นคะแนน/ประวัติ/การตั้งค่าส่วนตัว

ใช้ชื่อสมาชิก ClearPath แก้ไขได้ 3–40 ตัวอักษร ไม่ใช้ชื่อ Google อัตโนมัติ ซ่อนจากอันดับแล้วยังเห็น XP ส่วนตัว โดยไม่แสดง public profile สำหรับสมาชิกที่ซ่อน

รายงานนิรนามไม่มี member ID ชื่อ ยศ รูป Google หรือลิงก์บัญชี API สาธารณะไม่คืน Auth UUID; ช่อง user_id เดิมเป็น public member ID หรือ token แยกต่อรายงานเพื่อรักษา contract กับ client ลิงก์รูปแบบ opaque อายุสั้นไม่เปิดเผย Storage path ซึ่งอาจมี Auth UUID

การไม่นับรายงานตัวเองใช้ `/community/me/report-ids` ที่ยืนยันตัวตนเท่านั้น การนับผู้รายงานอิสระและการคำนวณฝุ่นใช้เจ้าของจริงฝั่ง server ตามเดิม

## ข้อมูลและงานเบื้องหลัง

- ตาราง XP accounts, append-only events, help claims, jobs และ rollout control เป็น service-only เปิด RLS แต่ไม่เปิดสิทธิ์ anon/authenticated
- Trigger บันทึก outbox พร้อมผลตัดสินอัตโนมัติ ไม่มี backfill รายงานเก่า
- Worker ทำ transaction มี lease/lock, unique constraints และเพดาน ตรวจพร้อมกันใน DB
- ประมวลผลทันทีหลังส่งและ retry ทุก 1 นาที ไม่ทำให้การส่งสำเร็จกลายเป็นล้มเหลวเมื่อ XP ขัดข้อง
- เวลา XP = server approval; เวลา recorded แยกสำหรับตรวจสอบย้อนหลัง
- Snapshot หลักฐานใน job ถูกล้างเมื่อทำสำเร็จ ประวัติ XP ไม่เก็บพิกัดหรือภาพ
- Admin ดู metrics/เหตุผล/รายการล่าสุด และ reversal พร้อมเหตุผลได้ ไม่เปลี่ยนผลรายงานหรือ Trust
- รูปแบบช่วยซ้ำเป็นสัญญาณตรวจสอบ ไม่มีการแบนอัตโนมัติด้วย IP/อุปกรณ์

## การตรวจสอบ

`node scripts/test-community-xp.mjs` รัน migration และ SQL transaction จริงบน PGlite ครอบคลุม outbox, retry, quota, cooldown, 65 XP, หลายผู้ช่วย, grace, reversal, ties, RLS, maintenance และ reset/restore snapshot

ชุด Python ตรวจ pure rules, service concurrency, API/สิทธิ์, anonymous privacy, backup encryption/tamper/approval guard; frontend ตรวจ period response races, alias/opt-out, ownership และ submission เดิม

ต้องตรวจ Safari บน iPhone จริงก่อนเปิด production การจำลองขนาดหน้าจอใน Chromium ไม่ใช่ผลยืนยันบนเครื่องจริง
