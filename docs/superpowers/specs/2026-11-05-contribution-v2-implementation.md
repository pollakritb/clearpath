โบนัสคำขอมีลำดับก่อนโบนัสภารกิจ ไม่มีการบวกซ้ำจากสองเหตุการณ์

Ledger ใช้เหตุการณ์อ้างอิงและเวอร์ชันกติกา มีคีย์กันซ้ำและการล็อก worker
ทำงานซ้ำไม่เพิ่มคะแนนอีก การประมวลผลช้าไม่ย้ายคะแนนไปเดือนที่ worker ทำงาน
การใช้โควตาที่ถูกยกเลิกภายหลังไม่เปิดโควตาให้ส่งวนเก็บคะแนนใหม่

## คะแนนหลักฐานและประวัติ

คะแนนหลักฐานเป็นคะแนนเต็ม 100 แยกจากคะแนนสะสม:

- ภาพ/การอ่านค่า 40: อ่านเลข 20, ระบุช่อง PM2.5 10, ระบุหน่วย 10
- เวลา/ที่มาภาพ 30: เชื่อมหลักฐานภาพ 15 และอายุภาพขณะส่ง 15/10/5
- ตำแหน่ง/บริบท 30: GPS 20/15/10, ความสอดคล้อง 5, บริบทที่ระบุ 5

ข้อมูลที่ไม่ทราบได้ 0 ในคะแนนเต็มเดิม ไม่เฉลี่ยใหม่เฉพาะส่วนที่มีข้อมูล
คะแนนนี้ไม่ใช่โอกาสที่ค่าฝุ่นถูกต้อง ไม่ใช้คะแนนสะสม ประวัติชื่อเสียงเดิม
ไลก์ ความนิยม หรือความเหมือนกับ Air4Thai/CAMS มาเพิ่มคะแนน
การอ่านเลขได้ไม่เท่ากับการเห็นหน่วยหรือยืนยันว่าเครื่องแม่นยำ

OCR เก็บข้อมูลช่อง PM2.5 และหน่วยแยกเป็น true/false/unknown เมื่อเปิดโค้ด v2
Publication ยังยึด number-only: อ่านเลขได้เผยแพร่ อ่านไม่ได้ปฏิเสธอัตโนมัติ
ไม่มีคิวให้ Admin อนุมัติ ฟอร์มเพิ่มบริบท เครื่องวัด และช่วงเฉลี่ย โดยเลือกไม่ทราบได้
การเก็บคะแนนหลักฐานล้มเหลวไม่ย้อนลบรายงานที่ตัดสินและเผยแพร่สำเร็จแล้ว

สถานะเครื่องแยกเป็นไม่ทราบ / ระบุรุ่น / มีผลประเมินอิสระ พร้อมวิธีและช่วงใช้ได้
การติ๊กว่าสอบเทียบเองไม่ทำให้ได้สถานะประเมินอิสระ

ประวัติผู้ใช้แสดงผ่าน/พบปัญหา/ยังสรุปไม่ได้ แยกภาพ เมทาดาทา วิธีเก็บข้อมูล
และเครื่องวัด อัตราผ่านใช้เฉพาะผลที่สรุปได้ พร้อมจำนวนตัวอย่าง
ไม่มีข้อมูลจะแสดง “ยังมีประวัติไม่เพียงพอ” ไม่มีคะแนนเริ่มต้น 50 ที่ทำให้เข้าใจผิด
ผล OCR อนุมัติไม่ถูกนำมานับเป็นผลตรวจอิสระ

ผลตรวจอิสระนำเข้าผ่าน server CLI/RPC ที่เก็บหลักฐานอ้างอิงและกันการนำเข้าซ้ำ
ไม่มีปุ่มแก้ผลหรือเพิ่ม/ลบคะแนนใน Admin ผลตรวจพบปัญหาสามารถกันรายงานออกจาก
การวิเคราะห์ โดยเก็บ snapshot คะแนนขณะส่งเดิมไว้ การยกเลิกคะแนนต้องมีผลยืนยัน
ที่ระบุว่า contribution ใช้ไม่ได้ ไม่ได้เกิดจากโหวตหรือการอ่าน OCR พลาดโดยลำพัง
โบนัสวัน/สัปดาห์ที่พึ่งพารายงานนั้นถูกตรวจซ้ำและชดเชยแบบไม่ทำซ้ำ

## Backend gap-fill และข้อมูลแผนที่

นโยบายคะแนนหลักฐานกับ gap-fill ใช้ release pointer เดียวกัน
ต้องมีหลักฐานสำคัญครบ รายงาน approved/fresh กลางแจ้ง ไม่ติดแหล่งกำเนิด
GPS ใช้ได้ ไม่ซ้ำ ไม่มีสถานีทางการสดใน 5 กม. และมีอย่างน้อย 2 ผู้รายงาน
จากแหล่งวัดอิสระภายใน 2 กม./1 ชม. โดยนับรายงานเป้าหมายรวมใน 2 ราย

แหล่งวัดที่ไม่ทราบตัวตนจะไม่ถูกสมมติว่าอิสระเพราะใช้คนละบัญชี
Private source key ได้จากผลตรวจเก็บข้อมูลอิสระ ไม่เปิดเผยในรายงานสาธารณะ
สถานะสอบเทียบเครื่องไม่มีทางลัดผ่านเกณฑ์นี้

ข้อมูลเก่าไม่มีคะแนนหลักฐาน v2 จะไม่ถูกเติมคะแนนจากค่าเริ่มต้นย้อนหลัง
Place IDW วง 2 กม. และการให้น้ำหนักตามระยะทางยังใช้กติกาเดิม
ไม่มีการเอาค่าฝุ่นไปคูณคะแนนหลักฐาน

เกณฑ์ 70 ใช้เป็น candidate สำหรับการทดสอบ local/offline เท่านั้น
ยังไม่มีการศึกษาภาคสนามหรือชุดประเมินอิสระจริงในงานรอบนี้
เครื่องมือประเมินตรวจการรั่วข้ามกลุ่ม train/test และรายงาน false inclusion/exclusion
กับช่วงความไม่แน่นอนได้ แต่การผ่าน fixtures ไม่ใช่การรับรองความแม่นยำจริง

## Leaderboard และหน้ามือถือ

ค่าเริ่มต้นรุ่นใหม่เป็นเดือนปฏิทิน เลือกเดือนย้อนหลังหรือทั้งหมดได้
เดือนแรกนับตั้งแต่วันเปิดกติกาใหม่ คะแนนเสมอกันใช้อันดับร่วม เช่น 1,2,2,4
ไม่ใช้ Trust เป็นตัวตัดสิน ไม่แสดงผู้ที่ซ่อนจากอันดับ แต่เจ้าของยังเห็นคะแนนตนเอง

หลังสิ้นเดือน 72 ชั่วโมงจะปิดรอบ มีเลข revision
ถ้ามีงานล่าช้าหรือชดเชยคะแนน จะสร้าง revision ใหม่และเก็บผลเก่าเป็น audit
ยศอิงคะแนนสะสมเดิมต่อเนื่อง ไม่ลดจากการหยุดใช้งาน

โปรไฟล์แสดงคะแนน/อันดับเดือนนี้ ความคืบหน้า 5 วัน ประวัติผลตรวจ และภารกิจ
ผลหลังส่งแยกโบนัสแต่ละรายการออกจากจำนวนคำขอที่ตอบ
หน้าหมุดเพิ่มคำอธิบายคะแนนหลักฐาน รายการที่ยังยืนยันไม่ได้ และเหตุผลการใช้ข้อมูล
Public profile แสดงประวัติเฉพาะสมาชิกที่เปิดโปรไฟล์ ไม่เชื่อมรายงานนิรนามกลับหาบัญชี

## ภารกิจพื้นที่

เริ่มจากศูนย์กลางสาธารณะ 3 บริเวณ: ตัวเมืองนครปฐม กำแพงแสน และสามพราน
ยังไม่ได้สร้างภารกิจทุกพื้นที่ทั่วประเทศ ใช้วง 2 กม. ตรวจทุก 15 นาที อายุ 60 นาที
ไม่มีสถานีสดภายใน 5 กม. และไม่มีรายงานกลางแจ้งที่หลักฐานใช้ได้ภายใน 2 กม./60 นาที
จึงประกาศงานไว้ก่อนผู้ใช้วัด ไม่สร้างภารกิจย้อนหลังให้รายงานที่ส่งมาแล้ว

ภารกิจซ้อนกันไม่เพิ่มโบนัสหลายรอบ มีการปิดงานที่ครอบคลุมแล้ว
งานส่งภายในเวลาที่กำหนดยังตรวจรับได้เมื่อ worker ทำงานช้า
กดจากรายการภารกิจไปดูจุดศูนย์กลางบนแผนที่ได้
ไม่ใช้พิกัดบ้านหรือที่ทำงานส่วนตัวเป็นตำแหน่งภารกิจสาธารณะ

## โหวตและ GPS

ใช้ 500 เมตรชั่วคราวตามคำสั่งผู้ใช้ล่าสุด ไม่อ้างว่าเป็นระยะที่งานวิจัยรับรอง
เงื่อนไขคือระยะ haversine + ความคลาดเคลื่อนผู้โหวต + ความคลาดเคลื่อนจุดวัด ≤500
คร่อมขอบเขตให้ขอตำแหน่งใหม่ ตำแหน่งใหม่ต้องอายุไม่เกิน 60 วินาที
รายงานต้องอายุไม่เกิน 3 ชั่วโมง ห้ามโหวตตนเอง คนละหนึ่งปฏิกิริยาต่อรายงาน
เปลี่ยนหรือถอนได้ และต้องเลือกเหตุผลเมื่อไม่ถูกใจ

Like/Dislike/Comment ไม่เพิ่มคะแนนหรือ Trust ถอนโหวตไม่ต้องใช้ GPS
ไม่มีการเก็บพิกัดผู้โหวตไว้ในรายการโหวตหรือคืนระยะจริงให้ browser
GPS จาก browser เป็นตำแหน่งที่อุปกรณ์รายงาน ไม่ใช่หลักฐานป้องกันการปลอมตำแหน่งสมบูรณ์

## เปิดใช้และย้อนกลับ

ไฟล์ migration: `supabase/migrations/20261105103332_contribution_evidence_v2.sql`
เพิ่มโครงสร้างแบบ additive โดยไม่รีเซ็ต ledger เดิม ค่าเริ่มต้นยังเป็น v1
RLS/grants ของ outcome, device evidence, mission, season และ control เป็น server-only

1. ทดสอบ migration กับฐานข้อมูล staging และสำรอง baseline ผ่าน
   `scripts/community_v2_release.py baseline --output <private-file>`
2. เปิด flags ของโค้ดและ automatic matching ให้พร้อมทุก instance แต่ pointer ยัง v1
3. ประเมิน threshold ด้วยหลักฐานอิสระจริง ใช้ `scripts/community_evidence.py evaluate`
   และเก็บ artifact อ้างอิง ไม่ใช้ผลจำลองแทนข้อมูลจริง
4. ให้ worker ระบายงานเก่าและ submission ที่ยัง pending แล้วใช้ server release CLI
   `activate --apply --threshold <evaluated-cutoff> --evaluation-ref <artifact-reference>`
5. Cron เดิม `scripts/sql/community_xp_scheduler.sql` เรียก worker ทุกนาที
   คะแนน ภารกิจ การชดเชย และปิดฤดูกาลไม่พึ่งการเปิดหน้าผู้ใช้
6. Rollback ด้วย `rollback --apply` เปลี่ยน pointer กลับ v1 เก็บ ledger v2 ที่ได้แล้วไว้
   งานที่รับไว้ก่อน rollback ยังถือเวอร์ชันเดิม จึงไม่รับทั้ง v1 และ v2 ซ้ำ

ในรอบนี้ไม่ได้เรียกคำสั่ง activate/rollback กับฐานข้อมูล hosted
ไม่ได้ commit, push หรือ deploy
